# 한전 SRM 발전사 입찰공고 사이트

한국서부·남부·중부·남동·동서발전의 입찰공고를 한 화면에 모아서 보여주는 사이트입니다.

## 어떻게 동작하나요

1. **직접 실행할 때만** GitHub Actions가 한전 전자입찰계약정보 API에서 공고를 받아 저장합니다. (자동 실행은 없습니다)
2. 저장소가 바뀌면 Vercel이 사이트를 자동으로 다시 배포합니다.
3. 사이트는 저장된 파일을 읽어서 목록으로 보여줍니다.

## 수집 방법 (Actions 탭 → 공고 수집 → Run workflow)

- **시작일 / 종료일**: 공고일 기준입니다. 예: `2021-09-21`
  - 비워두면 시작일은 오늘부터 5년 전, 종료일은 오늘부터 29일 뒤로 잡습니다.
- 시작일부터 종료일까지를 **90일 단위 구간으로 나눠서, 오래된 구간부터 순서대로** 요청합니다. (구간마다 발전사 5곳을 하나씩 요청)
- 이미 저장된 공고는 **지우지 않고 그대로 두고**, 새로 받은 공고를 합칩니다. 같은 공고번호는 최신 내용으로 덮어씁니다.
- 일부 구간이 실패하면 나머지는 저장하고, 실패한 구간을 화면 위쪽과 실행 로그에 표시합니다. 그 구간만 시작일·종료일을 좁혀서 다시 실행하면 됩니다.

## 폴더 구성

```
index.html                     화면 (검색, 기간, 발전사 선택, 공고 상세, ✕ 제외)
data/bids.json                 목록용 공고 (공고번호·공고명·공고일·마감일 등 가벼운 정보)
data/detail/YYYY-MM.json       상세용 (참가자격·첨부파일). 공고월별로 나뉘고, 공고를 눌렀을 때만 불러옵니다
scripts/collect.mjs            API에서 공고를 받아오는 프로그램
.github/workflows/collect.yml  수집을 실행하는 설정
```

## 처음 한 번만 하는 설정

### 1. GitHub 저장소 만들기
GitHub에 로그인해서 새 저장소를 만드세요. 인증키는 코드가 아니라 아래 3번의 Secrets에만 들어가므로 공개/비공개 어느 쪽이든 노출되지 않습니다.

### 2. 파일 올리기
저장소 화면에서 **Add file → Upload files**를 누르고, 이 폴더 안의 `index.html`, `data`, `scripts`를 끌어다 놓은 뒤 저장(커밋)하세요.

`.github`는 숨김 폴더라 업로드가 되지 않습니다. **Add file → Create new file**을 누르고 파일 이름 칸에 `.github/workflows/collect.yml`을 입력한 다음, 이 폴더의 `collect.yml` 내용을 붙여넣고 저장하세요.

### 3. 인증키 등록
저장소의 **Settings → Secrets and variables → Actions**로 들어가서 **New repository secret**을 누르세요.

- Name: `KEPCO_API_KEY`
- Secret: 발급받은 인증키 (40자리)

인증키는 여기에만 입력하세요. 코드 파일이나 채팅에는 적지 마세요.

### 4. 수집 실행
저장소의 **Actions** 탭에서 왼쪽 **공고 수집**을 고르고 **Run workflow**를 누르세요. 끝나면 `data/bids.json`이 공고로 채워집니다. 실패하면 실행 기록을 열어 **공고 수집** 단계의 메시지를 확인하세요. (인증키는 메시지에 나타나지 않도록 처리되어 있습니다.)

### 5. Vercel에 배포
vercel.com에 GitHub 계정으로 로그인한 뒤 **Add New → Project**에서 이 저장소를 가져오세요(Import). Framework Preset은 **Other**, Build Command는 비워두고 **Deploy**를 누르면 주소가 생깁니다. 이후에는 데이터가 갱신될 때마다 자동으로 다시 배포됩니다.

## 알아둘 점

- 화면의 **기간**과 정렬은 **공고일** 기준입니다. 마감일은 목록의 날짜에 마우스를 올리거나 공고를 눌러 상세 화면에서 볼 수 있고, 마감이 지난 공고는 흐리게 표시됩니다. (마감일 = 입찰종료일시, 개찰 전 최종 마감)
- 처음 열면 **최근 30일** 공고가 보입니다. 더 오래된 공고는 **전체** 또는 기간 입력칸으로 찾으세요. 목록은 200건씩 보여주고 **더 보기**로 늘립니다.
- 화면의 기간 설정은 이미 저장된 파일 안에서 거르는 조건일 뿐이고, API를 새로 호출하지 않습니다. API 호출은 Actions에서 **Run workflow**를 눌렀을 때만 일어납니다.
- **✕로 제외한 공고**는 사용 중인 브라우저에 저장됩니다. 다른 기기와는 공유되지 않아요.
- 구간 길이(90일), 기본 기간(5년), 요청 사이 대기 시간은 `scripts/collect.mjs` 위쪽에서 바꿀 수 있습니다.
- 참가자격 본문은 10,000자까지만 저장합니다.

## 실제 데이터로 아직 확인하지 못한 것

- API가 한 번에 돌려줄 수 있는 건수에 제한이 있는지: 수집 로그에 "건수가 딱 떨어져요"라는 안내가 나오면 알려주세요. 그 구간은 더 짧게 나눠서 다시 받아야 할 수 있습니다.
- API에 하루 호출 횟수 제한이 있는지: 5년치 수집은 요청이 100번 넘게 나갑니다. 중간에 오류가 나면 로그를 알려주세요.
- 5년 전 공고까지 실제로 조회되는지: API가 오래된 공고를 제공하는지는 실행해 봐야 알 수 있습니다.
- 공고가 없는 발전사를 조회했을 때 API가 어떻게 응답하는지: 오류로 응답하면 화면 위쪽에 "수집 실패"로 표시됩니다.
- 정정공고가 같은 공고번호로 올라오는지 새 번호로 올라오는지: ✕ 제외가 공고번호 기준이라 확인이 필요합니다.
- 첨부파일 링크가 로그인 없이 열리는지: 링크는 한전 SRM 서버 주소입니다.
